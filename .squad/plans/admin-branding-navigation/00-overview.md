## Dependency notes

- **This feature completes a three-story arc, it does not start a new one.** Story 62 created `BrandingConfig` (`admin` schema, one row per branch) and the admin form; Story 82 made the logo and `primaryColor` render live in both apps' persistent headers. Story 129 adds the remaining two fields — `appName` and `navigationLayout` — to that *same* row and that *same* form. Any future branding work should extend `BrandingConfig` the same way rather than introducing a second settings store.
- **The navigation source of truth moves, and must only move once.** Story 129 extracts `NAV_GROUPS`/`NavLinkItem`/`NavGroup`/`NavItemLabel` and the active-route rule out of `apps/web/src/components/workspace/workspace-nav.tsx` into `nav-items.tsx`, then deletes `workspace-nav.tsx`. Every later story that adds a workspace destination appends to `NAV_GROUPS` **there** — the "append as the new last entry, same convention" precedent that file's doc comment records for Stories 51/56/57/61/62/81/91/120 and RM-20/RM-22/RM-23/RM-27 carries over unchanged.
- **`workspace-nav.tsx`'s own "no sidebar" decision is superseded only under an explicit opt-in.** The Workspace Navigation UX audit deliberately declined a sidebar (see that file's doc comment, ~lines 210–214). Story 129 does not reverse that judgement for everyone: `NAVBAR` stays the resolved default for every unconfigured branch, and the sidebar exists only for a branch whose admin chooses it.
- **Deliberately deferred here:** pointing the S-1 `--accent` token at a branch's `primaryColor`. `packages/config/tailwind-tokens.css` (~lines 62–72) names that as its own future story ("Story S-15"); folding it into Story 129 would recolour every button in the app off an arbitrary admin-supplied hex, with a real contrast risk and no acceptance criterion asking for it.
- **`apps/portal` is untouched.** `GET /portal/branding` widens because it shares `BrandingSummary`, but the portal declares its own narrower interface (`apps/portal/src/lib/branding-api.ts`, lines 11–15) and ignores both new fields. Portal navigation redesign is an explicit intake non-goal.
- **Stray scaffold:** `.squad/plans/navigation-layout-customization/` and `.squad/stories/navigation-layout-customization/admin-branding-navigation-layout-customization/` were created by a `squad new-story` run under a different slug. Only the intake there holds content; its `00-overview.md` is an unfilled template. The plan lives here, under the intake's own declared slug. The stray folder is left as-is — the same treatment `00-index.md` already gives `slabusiness-hours-awaretargetcomputation` and `test`.
