## Workflow: one Story → one Plan (mandatory from RD-1.10 onwards)

Every remaining roadmap Story (RD-1.10 … RD-7.8) is executed as:

1. `squad new-story <story-title>` — `<story-title>` is **kebab-case** (e.g. `surfaces-and-overlays`), created **without a tracker ID** (`--no-tracker`). This scaffolds `.squad/stories/<story-title>/<id>/intake.md`; the intake is completed with the requirements from that Story's section of [`00-overview.md`](./00-overview.md).
2. `squad new-plan` → select that intake → the planner writes exactly one plan, `.squad/plans/<story-title>/NN-story-<story-title>.md` (`NN` = the next global sequence number).
3. Review the plan → implement → verify → commit (`feat(story-NN): …`, including the intake and plan) → push.
4. Record the Story here: a row in **Stories** below and a row in the **Story / Plan cross-reference**.

Rules:

- One intake, one plan, one Story, one commit. A plan never covers several roadmap Stories; a roadmap Story never has several plans.
- **Never** run `squad new-story` / `squad new-plan` with the feature slug `crm-ui-ux-redesign`. That folder is the track's umbrella (roadmap, recon, progress, independent QA review): the planner's output rules update `plans/<feature-slug>/00-overview.md`, which here is the 71-Story roadmap and must not be rewritten.
- No roadmap Story is implemented from the roadmap alone.
